# Game AI Atlas

An open, bilingual directory of open-source AI projects based on existing video games.

Search for a game and see the agents, remakes, mods, training environments, world models and tools built around it, with the latest GitHub activity, license and requirements.

- **Site:** [pabwass.github.io/game-ai-atlas](https://pabwass.github.io/game-ai-atlas/) (once deployed)
- **Español:** [README.es.md](./README.es.md)
- **Data:** curated YAML + automatically synced GitHub metadata
- **Stack:** Astro, TypeScript, Tailwind CSS, MiniSearch, GitHub Pages

## What it does

- Instant search by game title, alias or project name, accent-insensitive.
- Game pages with specific projects and compatible multi-game tools.
- Clear relationship labels: agent, clone/remake, mod, environment, world model or tool.
- Last commit, stars, license, language and archived status from GitHub.
- Practical flags: requires the original game, uses original assets, playable in browser, demo available.
- Bilingual UI and content: Spanish and English.
- Static, fast and accessible: no login, no database server, no tracking.

## Quick start

Requirements: Node.js 22.23+ and npm.

```bash
npm install
npm run dev
```

Open <http://localhost:4321/es/>.

Useful commands:

```bash
npm run validate      # validate YAML data and cross-references
npm run check         # Astro/TypeScript checks
npm run build         # validate, build search index and static site
npm run sync:github   # refresh GitHub metadata (requires GH_TOKEN)
npm run preview       # preview the production build
```

For the GitHub sync locally:

```powershell
$env:GH_TOKEN = (gh auth token)
npm run sync:github
```

## Data model in one minute

Each game lives in `src/data/games/<slug>.yaml`. Each project lives in `src/data/projects/<slug>.yaml`.

```yaml
id: farama-foundation-vizdoom
name: ViZDoom
repo: Farama-Foundation/ViZDoom
games: [doom]
game_scope: specific
relation: environment
ai_role: research
tech: [reinforcement-learning]
description_es: Entornos de RL para crear bots que juegan a Doom usando solo píxeles.
description_en: RL environments for building bots that play Doom using only pixels.
requires_original_game: true
uses_original_assets: true
playable_in_browser: false
license: MIT
tags: [fps, research]
review_status: approved
```

The GitHub metadata (stars, last commit, archived, license detection) is generated by `scripts/sync-github.mjs` into `src/data/generated/github.json`. Do not edit that file by hand.

See [docs/DATA.md](./docs/DATA.md) and [docs/TAXONOMY.md](./docs/TAXONOMY.md) for the full schema.

## Open data

The build generates static, machine-readable endpoints:

- `/api/games.json` — game catalog with counts, aliases and URLs.
- `/api/projects.json` — curated projects, GitHub metadata, links and flags.
- `/api/meta.json` — generation date and endpoint index.
- `/llms.txt` — compact context for AI agents.

The generated files are not committed; they are produced by `npm run build:search` during the build.

## Deploy to GitHub Pages

1. Create a public repository (for example `game-ai-atlas`).
2. Push this project to the `main` branch.
3. In **Settings → Pages**, set **Source** to **GitHub Actions**.
4. The `Deploy` workflow builds and publishes the site.
5. The scheduled `Sync GitHub data` workflow refreshes metadata and redeploys daily.

The workflow detects project pages (`/repo-name`) and user pages (`/`) automatically. If you use a custom domain, set `SITE_URL` in both workflows and update `site` in `astro.config.mjs`.

## Contributing

Read [CONTRIBUTING.md](./CONTRIBUTING.md). The short version:

1. Open an issue with the **Add project** or **Add game** form, or send a pull request.
2. Add one YAML file, following the schema.
3. Run `npm run validate` and `npm run build`.
4. A human reviews the relationship with the game, the license and the links.

AI-assisted contributions are welcome. See [AGENTS.md](./AGENTS.md) for the conventions other agents should follow.

## Inclusion criteria

- Public, open-source repository with a visible license.
- AI is central to the project, not an anecdotal use.
- A verifiable relationship with an existing game.
- No ROMs, ISOs, original assets, piracy links or malware.
- No forks without meaningful changes.
- A short, objective description with links to the source.

This site links to third-party projects. We do not host games, assets or third-party code. Some projects require a legal copy of the original game.
