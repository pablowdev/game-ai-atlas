# Taxonomy

The catalog answers four questions for every project:

1. **What is it?** — relation with the game.
2. **How is AI involved?** — AI role.
3. **How close is it to the original?** — fidelity, only for remakes.
4. **How wide is its scope?** — one game, several games, or general tooling.

## Relation

### `agent`

The AI plays the game. It can be a reinforcement-learning bot, a search engine, an LLM agent or a classical game AI.

Examples:

- Stockfish (chess)
- Voyager (Minecraft)
- PokemonRedExperiments (Pokémon Red)
- foul-play (Pokémon Showdown)

Use `agent` even if the project also provides a small API, as long as the main product is the playing AI.

### `clone`

A recreation or remake of the game, usually built with AI assistance. This is the category for "vibe-coded" browser remakes.

Examples:

- Claude of Duty (Call of Duty-inspired FPS)
- Kart Royale (Mario Kart-inspired racer)

If the project is a source port that does not use AI, it does not belong in this atlas. If it is an AI-generated remake, use `clone` and set `ai_role: built-with-ai`.

### `mod`

AI is added to the original game: conversational NPCs, generated dialogue, AI textures, AI-driven behaviour.

Examples:

- Mantella (Skyrim)
- SkyrimNet (Skyrim)
- RimWorld AI Framework (RimWorld)

A mod normally has `requires_original_game: true` and `uses_original_assets: true`.

### `environment`

An API, Gym/Gymnasium wrapper, benchmark or training environment for the game. It does not play by itself; it makes the game available to agents.

Examples:

- ViZDoom (Doom)
- PySC2 (StarCraft II)
- MineRL (Minecraft)
- ALE (Atari 2600)

Use `game_scope: multi` when the environment supports several games.

### `world-model`

A generative model that simulates the game from pixels/actions, often with diffusion. It is not a traditional clone because the game is generated by a model.

Examples:

- GameNGen repro (Doom)
- Diffusion Tetris (Tetris)

### `tool`

A framework or tool that helps build AI for the game but is not the agent, the clone, the mod or the environment itself.

Examples:

- Mineflayer (Minecraft bot API)
- RLBot (Rocket League bot framework)
- OpenSpiel (game research framework)

## AI role

### `built-with-ai`

The project was created with AI assistance. This does not necessarily mean AI runs inside the game. Use it for AI-generated or AI-assisted remakes and experiments.

### `runtime`

AI is part of the product at runtime: NPCs, generated content, bots, dialogue, voices.

### `research`

AI is trained, evaluated or studied. Most RL environments, benchmarks and research agents are `research`.

### `mixed`

More than one role is central. Use it sparingly; explain in the description.

## Fidelity

Fidelity only applies to `relation: clone`.

| Value | Meaning | Example |
|---|---|---|
| `exact` | Exact copy or port that uses the original game/assets. | A faithful engine port with original data. |
| `faithful` | Same core mechanics, new code and assets. | A remake that recreates the gameplay loop. |
| `inspired` | Inspired by the original, not a full recreation. | A browser game with a similar concept. |
| `partial` | A level, minigame or specific feature. | One Mario level recreated. |
| `n/a` | Not a clone. | Agents, environments, tools, mods. |

Be conservative. "Inspired" is better than overclaiming "faithful".

## Game scope

### `specific`

Built for one game, or for a small set of explicitly named games that share the same project. Example: a Doom-only environment.

### `multi`

A framework or environment that supports several games. Example: OpenSpiel supports many board and card games. These projects appear in a separate **Compatible tools** section on game pages, not in the main specific list.

### `general`

Not tied to a game. Example: Gymnasium, ML-Agents. These appear on the tools page and on the home page, not on individual game pages.

## Flags

- `requires_original_game`: the project needs a legal copy of the game to run.
- `uses_original_assets`: the project uses original art, audio or data. Legal caution; add the badge.
- `playable_in_browser`: it runs in a browser without a local game installation.
- `has_demo`: a public demo is linked in `links.demo`.

## Common edge cases

**A general RL library with an Atari example**: `game_scope: multi`, games include the Atari titles explicitly supported. Do not list it as `specific` for a single game.

**A mod that uses an LLM**: `relation: mod`, `ai_role: runtime`.

**A project that trains an agent and ships a Gym wrapper**: choose `agent` if the main product is the trained agent; choose `environment` if the main product is the interface. If both are central, use `mixed` for `ai_role` and explain.

**A remake with no AI**: exclude it. The atlas is about AI projects, not all fan games.

**A project that is only a paper**: exclude it unless there is public code. If the code is a small research repository, include it and link the paper.

**A closed-source demo**: exclude it from the main catalog. It can be mentioned in an issue as context, but the site is for open source.

**A project that violates an online game's terms**: include only if it is public, open source and relevant; add a warning in the description and do not present it as endorsed. Do not add cheats or malware.
